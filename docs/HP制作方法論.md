## PHASE 03 — 実装

### Standalone HTML の構造を理解して編集する

Claude Designの出力は「standalone HTML（単一ファイル）」形式で、内部にbundler構造を持つ。ブラウザだけで完全動作し、サーバー不要。

```html
<!-- ① 倉庫: CSS/JS を全部格納 -->
<script type="__bundler/manifest">
  /* ... 数百KBのコード ... */
</script>

<!-- ② 設計図: ページHTML全体をJSON文字列で保持 -->
<script type="__bundler/template">
  "<html>...ページ全体(～200KB)...<\/script>..."
</script>

<!-- ③ 組み立て係: 上の2つを読んで画面に展開 -->
<script>
  /* 起動コード */
</script>
```

**テンプレート境界の検出（重要）**

JSON文字列内に `</script>` タグが含まれる。`html.find('</script>')` では内側を誤検知するため、`html.find('"</script>')` を使って正確な末尾を特定する。

```python
tpl_s = html.find('<script type="__bundler/template">') + len(tag)
end_marker = '"</script>'   # JSONの閉じ " の直後が本物の閉じタグ
tpl_e = html.find(end_marker, tpl_s) + 1
tpl = json.loads(html[tpl_s:tpl_e])
```

**HTML内のエスケープ**

テンプレートJSON内のHTMLは以下のようにエスケープされている。直接テキスト検索するときはこの形式に合わせる。

| 元の文字 | JSON内での表記 |
|---|---|
| `<` | `<` |
| `>` | `>` |
| `"` (属性値) | `\"` |
| `</` | `<\/` |

## PHASE 04 — 資産処理

### ロゴ・画像を埋め込みまで処理するフロー

Standaloneファイルは画像もbase64としてHTML内に直接埋め込む。外部ファイル参照を持たないのでファイル単体で完全動作する。

**手順**

1. **解像度改善**: 低解像度ロゴ（50×35px）を Pillow LANCZOS で4倍拡大（200×140px）。知覚上のシャープさが向上する
2. **base64変換**: `base64.b64encode(img_bytes).decode()` → `data:image/png;base64,...` 形式で `src` 属性に埋め込む
3. **フッターロゴの白化**: CSS `filter: brightness(0) invert(1)` でロゴを白に反転。暗背景での視認性を確保
4. **NFDファイル名対応**: Mac由来の合成文字（「ゴ」=「コ」+ 結合濁点）が cp932 エンコードエラーを起こす。`os.listdir()` でバイト列として走査し、正常名にコピーして回避

**ファイル一覧**

| ファイル名 | サイズ | 用途 | style |
|---|---|---|---|
| `OG-logo-2x.png` | 200×140px | ヘッダー | `height:44px` |
| `logo_footer_01.png` | 321×140px | フッター | `height:80–90px; filter:brightness(0) invert(1)` |

## PHASE 05 — 反復改善

### 25MBファイルを安全に部分編集するしくみ

本体ファイルは25MBあり、直接編集するとエディタが重くなる。セクションだけを抽出した軽量ファイルで編集し、Pythonスクリプトで本体に書き戻すパターンを採用した。

**ファイル構成**

| ファイル | 役割 |
|---|---|
| `works_section_edit.html`（約10KB） | `<section id="works">` だけを切り出した専用編集ファイル |
| `merge_works.py` | 編集ファイルのセクションを本体に書き戻すスクリプト |

**merge_works.py のキーポイント**

```python
# テンプレートの正確な境界検出
tpl_s = html.find(TAG) + len(TAG)
end_marker = '"</script>'   # JSONの閉じ"の直後
tpl_e = html.find(end_marker, tpl_s) + 1

# 書き戻し時は </ をエスケープして再発防止
tpl_new_raw = json.dumps(tpl_new, ensure_ascii=False)
tpl_new_raw = tpl_new_raw.replace('</', '<\/')
```

> **注意**: `json.dumps` のデフォルトは `</script>` をエスケープしない。書き戻し後に `<\/` に置換しないと、次回読み込み時に境界検出が壊れる。

## PHASE 06 — 非AIデザイン実装

### 設計思想

AIが生成するデザインには共通の癖がある。それを意識して崩すことで、手で作られた印象を生む。

#### AIデザインの典型パターン（避けるべき）

- 全要素に `border-radius` が付いている（rounded-lg）
- クリーム地（#F4F1EA）＋セリフ体＋テラコッタアクセント
- Inter / Space Grotesk を「安全な」選択として使う
- 絵文字でセクションを区切る
- 全要素を中央揃えにする
- 等間隔の均一カードを3列に並べる
- 大見出しの `letter-spacing` がプラス値

#### 4つの原則

**1. 複数図形の重なり**

円・矩形・線をずらして重ねる。要素同士が「偶然そこにある」ような緊張感が手作り感を生む。AIはオブジェクトを整列させる傾向がある。

**2. 不規則性 — グリッドを意図的に破る**

等間隔グリッドは「テンプレート感」の最大の原因。飛び出す要素・わずかな角度が規則性を崩す。

**3. タイポグラフィの実践**

見出しの `letter-spacing` はマイナスが現代的。ラベルは大文字＋字間広め。AIが生成する `letter-spacing` はプラス寄りになりやすい。

**4. 中央揃えを崩す**

AIは全要素を中央に揃える傾向が強い。ヒーローの左寄せはエディトリアル誌の定石で、それだけで「設計された感」が出る。

---

### CSS注入 実装記録（10点）

Pythonで外部 `<head>` の直前に `<style id="__og_design_injection">` を注入。テンプレートJSONとは完全に分離しているため bundler の動作に影響しない。

```python
# 注入方法
head_close = html.find('</head>')   # pos 1,307（テンプレートとは別）
html_new = html[:head_close] + inject_css + html[head_close:]
```

## 再利用のための注意点

次回同様のプロジェクトで参照する際の注意点。

1. **テンプレート境界**: 必ず `'"</script>'` パターンで検出する。`html.find('</script>')` は誤検知する
2. **JSON書き戻し**: `json.dumps` の後に必ず `.replace('</', '<\/')` を実行する
3. **NFDファイル名**: Mac由来のファイル（Finder でコピーしたもの）は合成文字を含む場合がある。`os.listdir()` でバイト列比較して安全なファイル名にコピーしてから使う
4. **CSS注入の二重防止**: 注入する `<style>` に `id="__og_design_injection"` を付け、注入前に `id in html` で確認する
5. **モバイル対応**: hero の左寄せは `@media (max-width: 640px)` で中央揃えに戻す
